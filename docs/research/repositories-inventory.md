**The map says the two lists "converge … on the `origin` URL: a clone whose remote matches an ADO repository is that repository." On this disk, `matches` cannot mean string equality.** Exact equality joined 3 of 18; cosmetic normalisation added 0; aliasing the host joined 18.

The reason is one substitution, and it is not cosmetic: a clone taken before the `dev.azure.com` migration still says `{org}.visualstudio.com/{project}/_git/{name}`, and **ADO never reports that spelling back** — `remoteUrl` is always the `dev.azure.com` form. The host is therefore not part of a repository's identity; the triple org/project/name is. A join written on the URL as a string would report 15 of these 18 clones as unrelated to the organisation they were cloned from — silently, and looking exactly like a correct empty answer.

_Every `origin` on this disk parsed into an org/project/name triple._ That is this disk, not a guarantee: a fork, a mirror, a `file://` remote or a non-ADO origin all reach that code, and the parse returning `null` has to mean "cannot tell" rather than "no match".

**This section is evidence, not a licence to build the join.** The destination puts the join after both lists exist; what it buys here is knowing the join is possible and what it will cost when somebody writes it.
